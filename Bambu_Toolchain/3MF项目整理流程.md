# 把模型整理成可直接查看的拓竹多盘3MF

适用于用户提出“摆盘”“整理成拓竹项目”“给我一个3MF打开看看”。目标是交付**一套数量正确、位置明确、可编辑的拓竹项目**。

默认通过文件和拓竹后台命令完成，不操作桌面。除非用户另有要求，交付目录只放最终一个 `.3mf`；日志、试制、脚本与核验记录留在所属项目的工作文件和检查记录中。

## 1. 先明确本次到底打印什么

先查工作区项目索引和项目规则，确定唯一项目目录与本次版本。读取实际模型、尺寸及既有打印方向，不能只凭文件名把整个目录批量导入。

先写生产清单，再写摆盘清单：

- 每种零件指定唯一编号、明确源文件和本套数量；数量来自装配需要或用户要求。
- 排除备份、历史版、试片、验证副本、渲染参考和其它项目的模型。试片仅在用户明确要求时另设测试盘。
- 区分“网格种数”和“实际打印件数”：夹子一个文件打印两件，应有两次摆放记录，不能少一件，也不能整包重复一次。
- 专用白模、底座与遮盖片等配套件要来自同一兼容版本。

**禁止用目录通配符代替生产清单。** 不把“文件都带上，用户自己删”作为默认交付。

## 2. 选择实际设备的项目配置

优先复用同项目、同设备的有效拓竹3MF作为配置来源。确认机器型号、喷嘴、打印板、耗材数量与工艺；不能把某次的P1S/0.4/PLA当作所有项目的默认规格。

STL无单位，必须确认坐标使用毫米。保留已验证的打印方向、100%比例，只平移到盘面并落到Z=0。改方向或缩放应有本次任务依据。

单色工装通常只需一个耗材槽；若不需要，关闭冲刷塔、裙边及额外附着结构，避免出现意外附加打印。支撑、Brim等应按模型需要决定，不能为了“干净”而一律关闭。

**多色、多部件装配3MF不能直接拆成普通STL后再套本工具。** 需要保留部件关系、共同原点和耗材分配；本文脚本只覆盖已经确定打印朝向的单色STL生产件。

## 3. 摆盘并明确每盘内容

按机器有效打印区域和禁入区域安排，留出盘边距离与零件间距。大件一盘放不下就分盘；小件可放在同盘空处，不能靠重叠、悬空或把零件塞进另一个模型来省盘。

推荐盘名：`01_主体与夹子`、`02_底座`、`03_蓝色遮盖A`、`04_蓝色遮盖B补喷`。对象名也写清零件与数量。

检查：每盘件数、所有盘合计件数、各零件实际数量与生产清单一致；每个实体落地、比例与朝向正确，零件之间不碰撞、不超出有效板面或禁区，也不超过设备打印高度。

本工具采用保守包围盒间距检查，不做复杂嵌套排料；模型边界通过不代表Brim、支撑或最终路径也一定不越界。逐件打印需要更大的喷头避让范围，本工具不适用于该模式。

## 4. 写入真正的拓竹项目结构

需要同时保留标准3MF几何和拓竹项目的设备/工艺、对象/部件、盘号及实例对应关系。

特别注意：

1. **所有子网格的对象ID全局唯一，父对象ID也不得与其冲突。** 不要在多个 `3D/Objects/*.model` 文件中反复使用同一个 `objectid=1`。本机拓竹原生回读曾因此把不同名称的零件全部引用到第一个模型。
2. 需要多件的同一个零件可以共享网格资源，但打印实例必须按数量单独登记。
3. 项目对象、部件引用、根build实例、盘内 `model_instance`、源偏移和变换必须对应。
4. 多盘工作区的原点间距及列数按所用拓竹版本计算，不把所有盘放在同一个原点。当前验证版本按 `ceil(sqrt(盘数))` 分列，X/Y步距为对应板尺寸的1.2倍，下一行沿负Y方向；升级后需复核。
5. 不保留来自模板项目的旧模型、旧盘、旧缩略图或旧G-code。配置模板只用于取得有效配置。

这些细节已封装在 `plate_project.py` 中。不要复制某个项目硬编码的路径、盘数、机型或翻面参数。

## 5. 让拓竹原生后台读入并重新导出

使用本机Bambu Studio原生导出：

```text
bambu-studio.exe --arrange 0 --debug 3 --outputdir <ASCII工作目录> --export-3mf project.3mf input.3mf
```

`--arrange 0` 保留已经核对的分盘与位置；此步骤不加 `--orient`、`--scale` 或 `--slice`。中文项目路径通过现有工具的ASCII缓存暂存，日志及核验记录回到所属项目，不修改用户当前打开的工程。

**导出返回0、文件能解压，并不代表项目正确。** 下一步必须核对实际几何；检查通过后才把文件复制到最终交付位置。

## 6. 原生导出后的强制回读核验

至少检查以下项目，并保存 `verification.json`：

| 核验 | 通过条件 |
|---|---|
| ZIP与引用 | CRC正确，引用的模型文件、对象和部件真实存在 |
| 盘数与数量 | 逐盘数量、总实例数、各零件数量与清单完全一致 |
| 真实网格 | 每件面数、实际顶点位置/形状与源文件对应；不能只看对象名 |
| 尺寸与变换 | 毫米尺寸、100%比例、打印朝向、落地及摆放位置不变 |
| 板面 | 本盘模型不越界、不进入禁区，保留间距 |
| 配置 | 机型、喷嘴及耗材槽数与本次要求一致 |
| 附加内容 | 没有试片、旧版、备份、重复实例或旧切片G-code |

文件体积突然大幅缩水时应查明原因，不能把它自动理解为“压缩更好”。曾有一个错误包盘数和名称全部正确，但15个对象的实际几何都成了同一个白模；正是面数与真实几何回读发现了问题。

## 7. 交付与状态说明

一般只给一个最终 `.3mf` 链接，说明机型、盘数、生产件数量，以及是否已切片。不在打印项目中放说明用模型或试片。

- **已摆盘、未切片**：可编辑项目，用户打开确认后自行切片。
- **已切片**：需要另做G-code与配置回读核验；不要把后台重新导出称为完成切片。
- **直接打印文件**：遵循原工具链 `slice --print-file` 规则，用原生 `--min-save`，不能靠改扩展名产生。

GUI查看、实际切片、实物试印分别说明做没做。默认不发送打印任务。

## 使用共用脚本

把JSON示例复制到所属项目的 `工作文件/编号任务/plates.json`，再填写实际源文件、数量、盘名和中心位置。所有相对路径都相对该清单文件；模板3MF和模型必须在本项目内。示例中的 `../..` 指向项目根目录，不能直接在共用examples目录运行示例。

```powershell
python Bambu_Toolchain/plate_project.py --manifest 'Projects/项目名/工作文件/编号任务/plates.json' --work 'Projects/项目名/工作文件/编号任务/打包过程' --checks 'Projects/项目名/检查记录/编号任务' --out 'Projects/项目名/导出成品/编号任务/生产件_已摆盘_001.3mf'
```

脚本要求新的工作/检查目录及新的输出文件，拒绝覆盖；先核验生产数量，再构建项目、原生回读、核对几何，通过后发布最终文件。清单示例见 `examples/plate_project_manifest.json`。

免死鲸牌：13盘，15个生产件，14种网格；白模1、底座1、遮盖片11、夹子2。第1盘白模和两个夹子，第2盘底座，余下11盘各一片遮盖件；试片及旧版全部排除。该数量与P1S/0.4配置只属于此案例。

验证记录：`Projects/免死鲸牌_001/检查记录/008_拓竹整套摆盘_001/`。本规范不会移动或改写该项目的历史产物。

技术依据：[拓竹官方CLI](https://github.com/bambulab/BambuStudio/wiki/Command-Line-Usage)、[3MF读写源码](https://github.com/bambulab/BambuStudio/blob/master/src/libslic3r/Format/bbs_3mf.cpp)、[多盘布局源码](https://github.com/bambulab/BambuStudio/blob/master/src/slic3r/GUI/PartPlate.cpp)。当前实测Bambu Studio 02.08.02.61；其他版本需重新做原生回读验证。

共用脚本验证：已复现上述13盘15件项目；另用两种不同网格、两盘三实例做原生集成测试，并确认数量不符、重叠、越界、超高、重复名称、设备不符、覆盖已有输出及原生错误引用同一网格时均会拒绝发布。记录见 `Workspace_Admin/3MF流程固化_20261030_001/`，测试入口为 `tests/test_plate_project.py`。
